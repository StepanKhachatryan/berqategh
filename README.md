# ԲերքաՏեղ · Berqategh

Քարտեզային հարթակ, որտեղ Հայաստանի փոքր ֆերմերային տնտեսությունները վաճառում են
իրենց բերքը **ուղիղ գնորդին՝ առանց միջնորդի**։ Վաճառողը մեկ րոպեում տեղադրում է
հայտարարություն, գնորդը քարտեզի վրա գտնում է իրեն ամենամոտ առաջարկը և զանգահարում
ուղիղ։

> A GIS marketplace connecting Armenian smallholder farmers directly with buyers.
> Sellers post a five-day offer pinned to their location; buyers browse a live map
> and filter by road distance, price, product, fresh-or-dried and wholesale/retail
> channel.

---

## Ինչպես է աշխատում

**Մուտքի պատուհան.** Առաջին բացելիս համակարգը հարցնում է՝ **գնորդ եք թե վաճառող**։
Ընտրությունը պահվում է սարքում, և ամբողջ ինտերֆեյսը հարմարեցվում է այդ դերին։
Դերը ցանկացած պահի փոխվում է վերևի անջատիչով։

**Վաճառողի հոսքը**

| Քայլ | Ինչ է կատարվում |
| --- | --- |
| Ապրանք | Ընտրվում է ցանկից՝ ~90 մրգ, բանջարեղեն, հատապտուղ, կանաչի և ընկուզեղեն |
| Թարմ թե չիր | Չորացվող ապրանքների մոտ հայտնվում է «Թարմ / Չիր» ընտրություն։ Չիրն առանձին ապրանք չէ — նույն մրգի ուրիշ վիճակն է, ուստի ցանկը չի կրկնապատկվում |
| Վաճառքի ձև | Միայն մանրածախ / միայն մեծածախ / երկուսն էլ |
| Գին | Ակտիվանում են միայն այն գնի դաշտերը, որոնք համապատասխանում են ընտրված ձևին |
| Հեռախոս | Դաշտն արդեն ունի ամրակայված `+374`, լրացվում է միայն 8 նիշը՝ առանց առջևի զրոյի |
| Տեղադիրք | Որոշվում է ավտոմատ (GPS)։ Եթե վաճառողն այս պահին վաճառքի կետում չէ, քարտեզը շարժելով նշում է ճիշտ կետը։ Կետը պետք է լինի Հայաստանի սահմաններում |

Հայտարարությունը քարտեզին մնում է **5 օր**, ապա անհետանում է և արխիվացվում։
Վաճառողը «Իմ հայտարարությունները» բաժնում տեսնում է մնացած ժամանակը, կարող է
վաղաժամ հանել քարտեզից, ջնջել կամ արխիվից **կրկին հրապարակել** նոր 5 օրով։

### Messenger-ի և նման հավելվածների ներսում

Երբ հղումը բացվում է **Messenger-ի, Facebook-ի կամ Instagram-ի ներսի բրաուզերում**,
տեղադիրքի ավտոմատ որոշումը չի աշխատում։ Դա հավելվածի սահմանափակումն է, ոչ թե կայքի.
հավելվածը կա՛մ ընդհանրապես չի խնդրել համակարգից տեղադիրքի թույլտվություն, կա՛մ չի
փոխանցում այն իր ներսի բրաուզերին։ **JavaScript-ով դա հնարավոր չէ շրջանցել։**

Դրա համար հարթակը չի կռվում այդ սահմանափակման հետ, այլ.

1. **Ճանաչում է միջավայրը** (user agent-ով) և բացատրում է, թե ինչու չստացվեց՝ առանց
   օգտագործողին մեղադրելու։
2. **Առաջարկում է թույլտվություն չպահանջող ճանապարհ** — բնակավայրի անվան որոնում։
   Ֆերմերը գրում է իր գյուղի անունը, կետը հայտնվում է քարտեզին, հետո ճշտում է
   քարտեզը շարժելով։ Այս դաշտը միշտ առկա է, ոչ միայն սխալի դեպքում, քանի որ հաճախ
   ավելի արագ է, քան GPS-ի սպասելը։
3. **Առաջարկում է անցնել իրական բրաուզեր** — Android-ում `intent://` հղումով,
   iOS-ում `x-safari-https://`-ով։ Երկուսն էլ երաշխավորված չեն (հավելվածը կարող է
   լուռ անտեսել), ուստի «Պատճենել հղումը» կոճակը միշտ մնում է տեսանելի։

Այս պահին ներսի բրաուզերում geolocation-ի սպասման ժամանակը կրճատված է 6 վայրկյանի,
որպեսզի օգտագործողը չսպասի ապարդյուն։

**Գնորդի հոսքը.** Քարտեզ + ցանկ՝ ֆիլտրերով.

- **Հասանելիության շառավիղ կիլոմետրով** — հաշվարկվում է *ճանապարհի երկարությամբ*
  (OSRM), ոչ թե ուղիղ գծով։ Երբ երթուղիների ծառայությունը հասանելի չէ, ցուցադրվում է
  մոտավոր հեռավորություն՝ `≈` նշանով, որպեսզի պարզ լինի, որ թիվը գնահատական է։
- Մեծածախ / մանրածախ
- Առավելագույն գին՝ 1 կգ
- Կատեգորիա և կոնկրետ ապրանքներ
- Ազատ որոնում (հայերեն, լատինատառ կամ ռուսերեն արտագրությամբ՝ `լոլիկ`, `lolik`, `pomidor`)

### Սպասարկման տարածքը

Հայտարարությունը կարող է լինել **միայն Հայաստանի սահմաններում**։

Նախկինում ստուգումը լայնության և երկայնության ուղղանկյուն էր, բայց Հայաստանի շուրջ
գծված ուղղանկյունը ներառում է նաև Իրանի, Թուրքիայի, Ադրբեջանի և Վրաստանի հատվածներ։
Հենց այդպես մի հայտարարություն հայտնվել էր **Իրանի ներսում՝ 33 կմ խորությամբ**։

Հիմա ստուգումը երկրի իրական ուրվագծով է (OpenStreetMap), և կիրառվում է երկու տեղում.

- **Բազայում** — `service_area` աղյուսակ + PostGIS trigger, որը մերժում է սահմաններից
  դուրս ցանկացած տող։ Սա է վերջնական երաշխիքը։
- **Ինտերֆեյսում** — նույն ուրվագիծը (`src/data/armeniaBoundary.ts`), որպեսզի
  վաճառողը սխալի մասին իմանա, քանի դեռ կարող է ուղղել կետը, ոչ թե հրապարակելիս։

Ուրվագիծը պարզեցված է ~1.3 կմ ճշտությամբ և ընդլայնված ~1.1 կմ դեպի դուրս։ Երկու
ընտրությունն էլ միտումնավոր ներողամիտ են. սահմանամերձ գյուղը սխալմամբ մերժելը կորցրած
ֆերմեր է, իսկ սահմանից երկու կիլոմետր այն կողմ ընկած կետը ոչ մեկին չի խանգարում։

### Քարտեզի նշանները

Յուրաքանչյուր նշան միաժամանակ երկու բան է ասում.

| Ձևը | Իմաստը |
| --- | --- |
| ⬤ Կլոր քորոց | Միայն **մանրածախ** |
| ▢ Արկղ | Միայն **մեծածախ** |
| ⬡ Բազմանկյուն | **Մանրածախ և մեծածախ** |

**Գույնը** համապատասխանում է մրգի կամ բանջարեղենի իրական գույնին՝ լոլիկը կարմիր,
բադրիջանը մանուշակագույն, եգիպտացորենը դեղին և այլն։ Առևտրային տեսակետից կարևոր
տարբերությունը (վաճառքի ձևը) դրված է **ձևի** վրա, ոչ թե գույնի, որպեսզի այն
ընթեռնելի մնա նաև փոքր չափի և գունային ընկալման խնդիր ունեցող օգտատերերի համար։

## Տեխնոլոգիաները

| Շերտ | Ընտրություն |
| --- | --- |
| Frontend | React 18 + TypeScript + Vite |
| Քարտեզ | Leaflet + **OpenStreetMap** սալիկներ (CARTO Voyager ոճ) |
| Արբանյակ | Esri World Imagery — երկրորդ շերտը, որ դաշտն ու այգին տեսանելի լինեն |
| Երթուղիներ | OSRM `table` ծառայություն՝ ճանապարհային հեռավորության համար |
| Հասցեներ | Nominatim՝ հայերեն հասցեների համար (`accept-language=hy`) |
| Նավիգացիա | Yandex Maps և Google Maps՝ արտաքին հավելվածներ |
| Բազա | Supabase (Postgres + RLS + pg_cron) |
| Hosting | Netlify |

Քարտեզային հիմքը OSM-ի վրա է. արբանյակային շերտը լրացուցիչ տարբերակ է, ոչ թե
փոխարինում։

**Կոորդինատներ ոչ մի տեղ չեն ցուցադրվում։** «40.15530, 44.03670»-ը ոչինչ չի ասում ո՛չ
գնորդին, ո՛չ վաճառողին։ Դրա փոխարեն Nominatim-ից վերցվում է հայերեն հասցեն
(«Երկրորդ փողոց 14, Վեդի, Արարատի մարզ»)։ Եթե հասցեն չի գտնվում, տողն ուղղակի չի
ցուցադրվում — կոորդինատներով փոխարինում չկա։

## Տեղային աշխատանք

```bash
npm install
cp .env.example .env    # արժեքներն արդեն լրացված են
npm run dev             # http://localhost:5173
```

Այլ հրամաններ՝

```bash
npm run build        # production build → dist/
npm run preview      # ստուգել build-ը տեղում
npm run typecheck    # TypeScript ստուգում
```

### Միջավայրի փոփոխականներ

| Փոփոխական | Պարտադի՞ր | Նկարագրություն |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | ✅ | Supabase նախագծի URL |
| `VITE_SUPABASE_ANON_KEY` | ✅ | Publishable (anon) բանալի |
| `VITE_OSRM_URL` | ❌ | Սեփական OSRM սերվեր (default՝ հանրային demo) |
| `VITE_NOMINATIM_URL` | ❌ | Սեփական Nominatim (default՝ հանրային) |

`.env.production`-ը կոմիտ արված է, որպեսզի Netlify-ի build-ն աշխատի առանց լրացուցիչ
կարգավորման։ Publishable բանալին նախատեսված է հենց բրաուզերում հայտնվելու համար —
ինքնին ոչ մի իրավունք չի տալիս, բոլոր իրավունքները որոշվում են ներքևում նկարագրված
RLS քաղաքականություններով։

## Տվյալների բազա

Մեկ աղյուսակ՝ `public.listings`։ Միգրացիաները՝ `supabase/migrations/`։ Ցուցադրական
տվյալներ այլևս չկան — բազայում իրական հայտարարություններ են։

**Հաշիվներ չկան։** Յուրաքանչյուր բրաուզեր մեկ անգամ գեներացնում է պատահական
`owner_token`, պահում localStorage-ում և ուղարկում `x-owner-token` վերնագրով։ Հենց
դրանով է որոշվում, թե որ տողերը կարող է փոփոխել տվյալ սարքը։

`owner_token`-ը փաստացի գաղտնաբառ է. ով գիտի այն, կարող է արխիվացնել կամ ջնջել տվյալ
հայտարարությունը։ Դրա համար **անանուն օգտատերն այդ սյունակը կարդալու իրավունք չունի**
(սյունակային մակարդակի `grant`), իսկ բոլոր գրառումները, բացի հրապարակելուց, անցնում են
`security definer` ֆունկցիաների միջով։

| Գործողություն | Ինչպես է թույլատրվում |
| --- | --- |
| `select` | Միայն ակտիվ հայտարարությունները, բոլոր սյունակները **բացի `owner_token`-ից** |
| `insert` | Միայն սեփական `owner_token`-ով |
| `update` / `delete` | **Ամբողջությամբ արգելված է** client-ից |
| `my_listings()` | Վերադարձնում է տվյալ սարքի հայտարարությունները՝ ակտիվ և արխիվացված |
| `archive_listing(id)` / `delete_listing(id)` | Աշխատում են միայն սեփական տողերի վրա |

Արխիվացումն ու ջնջումը RPC են, ոչ թե ուղիղ `update`/`delete`, որովհետև Postgres-ը
`select` քաղաքականությունը կիրառում է նաև այն տողերի վրա, որոնք փոփոխվում կամ ջնջվում
են։ Արխիվացված տողն այլևս չի բավարարում հանրային քաղաքականությանը, ուստի ուղիղ
հարցումը մերժվում էր հենց **իր վաճառողի** համար։

> **Supabase-ի linter-ի մասին.** Dashboard-ը երեք `security definer` ֆունկցիաների համար
> ցույց է տալիս `Public Can Execute SECURITY DEFINER Function` զգուշացումը։ Դա
> **սպասելի է** — հարթակն ամբողջությամբ անանուն է, և յուրաքանչյուր ֆունկցիա ինքն է
> ստուգում `x-owner-token`-ը՝ նախքան որևէ բան փոխելը։ Linter-ը չի կարող տեսնել այդ
> ներքին ստուգումը։ Երբ ավելացվի իրական authentication, այս ֆունկցիաները պետք է անցնեն
> `auth.uid()`-ի վրա և դառնան `security invoker`։

5 օրվա ժամկետը կիրառվում է **և՛** կարդալու քաղաքականությունում, **և՛** հարցման
շերտում, ուստի հայտարարությունը քարտեզից անհետանում է ժամկետը լրանալու պահին, ոչ թե
արխիվացման հաջորդ գործարկմանը։ `pg_cron`-ի `archive-expired-listings` աշխատանքը
10 րոպեն մեկ միայն նշում է արխիվի դրոշը՝ պատմության և վիճակագրության համար։

Ցուցադրական տվյալները՝

```bash
psql "$DATABASE_URL" -f supabase/seed.sql
```

## Հաջորդ քայլերը (MVP-ից հետո)

- **Չարաշահման դեմ պաշտպանություն** — այս պահին ցանկացած ոք կարող է տեղադրել
  հայտարարություն։ Արտադրական թողարկումից առաջ արժե ավելացնել SMS հաստատում կամ
  գոնե rate limit-ի trigger `owner_token`-ի և IP-ի վրա։
- **Սեփական OSRM և Nominatim** — հանրային demo սերվերները rate limit ունեն և
  արտադրական օգտագործման համար նախատեսված չեն։
- Նշանների խմբավորում (clustering), երբ մեկ տարածքում շատ հայտարարություններ լինեն։
- Լուսանկարներ հայտարարությանը (Supabase Storage)։
- Push ծանուցումներ գնորդներին՝ իրենց շառավղում նոր բերք հայտնվելիս։
